# Buyer Technical Due Diligence

A strategic acquirer should be able to verify the following without relying on marketing claims.

## Code and IP

- Complete repository history.
- Contributor and contractor ownership records.
- Dependency licenses.
- Model/dataset licenses.
- Reproducible builds where supported.

## Security

- Threat model.
- Security architecture.
- Access-control tests.
- Cross-tenant isolation tests.
- Upload security tests.
- Secret scanning.
- Dependency and container scanning.
- Independent penetration-test report when available.

## Reliability

- CI history.
- Test results.
- Migration history.
- Backup/restore evidence.
- Disaster-recovery exercise records.
- Production incident history.

## Product

- API contract.
- Data inventory and findings workflows.
- PIA and remediation workflows.
- Connector contracts.
- Performance benchmarks generated from reproducible test runs.

## Commercial

- Customer contracts.
- ARR/MRR evidence.
- Retention and expansion metrics.
- Support history.
- Reference permissions.

This repository currently provides technical evidence for some controls, but it does not manufacture the independent, commercial or legal evidence above.
